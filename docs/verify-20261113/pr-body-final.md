## 这条分支干了什么

按业主「推倒重来 + 创造模式·全链路呈现 AWR 能力」的拍板，把 dsh-awr 的三个界面（头部 chip+Popover、进展页、会话行）从「只有一个空壳」重做成能诚实回答「目标是什么 / 离目标多远 / 现在轮到谁 / 下一步做什么」的工作台，并立下贯穿全页的**诚实法**：

- **零混合完成率**：AWR accounting 原话 never invent a blended completion percent——页面只数条数、每格自带口径 title、未开始画斜纹，全页 0 处百分比
- **AWR 原话不翻译**：台账事件、issue、finding 一律原文（是记录不是文案）
- **没读到 ≠ 读为空**：空态分 none / broken / filtered 三类，各说清为什么空、何时会满
- **doctor 不放行不许沉默**：error findings 上健康区、进『需要你处理』、附 AWR 自己给的 repair 命令；页面永远只读不执行修复
- **零 ULID**：内部 id 不进默认视图，revision 只进 tooltip

## 主要区块（按渲染序）

目标带 → 下一步三层卡（结论/归因/指标/展开）→ 此刻在做（会话→工作项，未认领保留标注）→ 台账大盘（主线×状态图例互为筛选器）→ 需要你处理 → 三视图筛选 → 台账事件（有界读取、原文照贴）→ 健康区（doctor findings 分行）→ 投入核算（合同未批准前如实留白）。另有源故障红色横幅（DSH-078）与 chip 徽章。
